# First users

| User | Workflow | Desired outcome |
|---|---|---|
| Solo developer | Ask an agent to verify a change before shipping | Reproducible failures rather than an unsupported “works” |
| Small product team | Run critical flows in a pull request | Existing tests plus targeted integration checks |
| Bot maintainer | Change dialogue handlers and buttons | State, roles and duplicate-event regressions caught early |

Primary use cases: verify a local web/API change; verify a bot conversation; verify a supported Android build using a configured runner. UX observations remain reviewable suggestions.
