# What a security result means

A **confirmed deviation** needs the declared requirement, current target identity/revision, executed negative scenario and actual response/effect. Reading another user's object despite a 403 ownership oracle is a confirmed access-control defect. A role check through the recorded aiogram dispatcher is a local handler result; it does not validate real Telegram transport.

A **potential issue** is a source credential pattern, advisory, Semgrep match or missing configured response header. Its location and rule are evidence; active credentials, reachable vulnerable code and exploitability require separate verification. Secret values and raw source snippets are withheld.

An **unverified area** includes a blocked scanner, missing credentials/device, unsupported language rule set, excluded files, endpoints outside the explicit scenario, Git history and third-party services. Failed findings, observations and blocked prerequisites are distinct statuses. A clean bounded scan does not certify an application, replace a penetration test or establish that all buttons work.

Tool names and scanned counts are recorded with each artifact. An empty or incomplete scan blocks instead of returning a clean result. UX observations are never converted into confirmed security defects. Priorities retain the declared requirement and configured impact; automated labels are subject to review.
